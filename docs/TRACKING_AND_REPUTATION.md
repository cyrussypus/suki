
# Delivery tracking and reputation

Tracking is available for `out_for_delivery`, the existing status for a dispatched delivery. A rider explicitly starts sharing from the active delivery screen; leaving it stops sampling. Android 11+ and iOS request foreground GPS fixes; Android 9–10 may use a fresh cached fix or manual reporting. The assigned rider sends telemetry to `GET /api/rider/location/stream?order_id=<id>` over WebSocket. Only the assigned rider and the order customer can use that stream. Sessions, assignment and status are checked throughout the connection; it closes on delivery or cancellation. The last location is removed on either transition. Existing order chat and location endpoints remain available to their original authorized users.

The customer map shows Bankerohan Market for weighted orders. Legacy orders use the currently configured pickup coordinates because historical orders did not record a pickup point. Map tiles come from OpenStreetMap and expose the viewed area to its tile service. `GET /api/orders/{id}/eta` uses the existing Google Routes configuration and a recent rider position; estimates are unavailable when the position is stale or the routing service is unavailable. Calls are limited to two per customer per minute per backend process.

Customers may submit separate reviews at `POST /api/orders/{id}/reviews/vendor` and `/rider` after delivery. Each accepts a rating from 1 to 5, an optional comment and up to three tags. Vendor tags are `quality`, `packaging`, `accuracy`; rider tags are `speed`, `handling`, `courtesy`. A unique order constraint per table prevents duplicate reviews. Scores are calculated from review rows under the recipient lock; `vendor_profiles` is the current stall model. A 5-star review earns 15 points, a 4-star review earns 10, and a third or later consecutive 5-star review adds 5. A rider receives 25 points on each tenth completed delivery. Historical delivery counts are backfilled, without retroactive points. `GET /api/reputation/{vendor|rider}/{id}` exposes aggregates to signed-in users.

Apply migration 0007 before deploying the new API. As with MariaDB DDL generally, take a backup before migration and investigate a failed partial migration before retrying. The point rules and default score of 5.00 apply to new review data; the review count indicates whether a score has any ratings. Live tracking requires a running backend and foreground location permission; it does not continue in the background.
